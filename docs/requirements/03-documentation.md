# 03. Репозиторий и документация

### DOC-001 — Исходные материалы в репозитории
Статус: обязательное. Источник: «Требования к Git-репозиторию».

Требование: разместить все нужные для воспроизведения исходные файлы, включая конфигурации Kubernetes, Gateway API, Prometheus, Fluentd/Filebeat и применённую автоматизацию.

Проверка: сверить опубликованные файлы с фактическим процессом развёртывания. Доказательство: пути к файлам и чистое развёртывание из клона.

### DOC-002 — Описание и архитектура README
Статус: обязательное. Источник: «1. Kubernetes-окружение»; «Требования к Git-репозиторию — README.md».

Требование: README.md содержит краткое описание решения, архитектуру, список технологий и версий, версию Kubernetes, способ создания кластера, название и версию реализации Gateway API и используемые ресурсы Gateway API.

Проверка: сверить разделы README с фактически развёрнутыми версиями и ресурсами. Доказательство: ссылки на разделы и вывод команд.

### DOC-003 — Среда и установка в README
Статус: обязательное. Источник: «1. Kubernetes-окружение»; «Требования к Git-репозиторию — README.md».

Требование: README.md указывает требования к среде, ОС фактического тестирования, все необходимые дополнительные компоненты и способ их установки, пошаговое развёртывание и команду или последовательность команд запуска.

Проверка: пройти инструкции на заявленной среде. Доказательство: раздел README и журнал запуска.

### DOC-004 — Проверки в README
Статус: обязательное. Источник: «3. Gateway API»; «4. Мониторинг»; «5. Логирование»; «Требования к Git-репозиторию — README.md».

Требование: README.md объясняет, как проверить приложение через Gateway API, какие метрики собираются и как проверить Prometheus, какие логи собираются, куда они поступают и как проверить сбор.

Проверка: исполнить инструкции для всех трёх путей. Доказательство: ссылки на инструкции и фактические ответы, метрики, логи.

### DOC-005 — Улучшения и ограничения в README
Статус: обязательное к описанию, если улучшения реализованы. Источник: «Возможности для улучшения решения»; «Требования к Git-репозиторию — README.md».

Требование: README.md описывает реализованные дополнительные возможности и известные ограничения; если улучшений нет, явно это указать.

Проверка: сверить заявленное с кодом и работающей системой. Доказательство: соответствующие разделы и проверки заявленных функций.

### DOC-006 — Отсутствие секретов в репозитории
Статус: обязательное. Источник: «Требования к безопасности».

Требование: не публиковать реальные пароли, API-токены, приватные SSH-ключи, персональные данные и иные секреты; необходимые секреты передавать безопасным способом.

Проверка: просмотреть публикуемые файлы и историю на секреты, проверить документированный способ передачи. Доказательство: результат проверки без раскрытия значений.

### DOC-007 — Паспорт: формат и объём
Статус: обязательное. Источник: «Требования к паспорту проекта — Формат».

Требование: подготовить паспорт не более 4 страниц и 15 МБ. Исходник допускает PDF или DOC/DOCX; для архива безопасный вариант имени и формата — `Паспорт.pdf` (см. DEC-001).

Проверка: проверить формат, число страниц и размер файла. Доказательство: свойства финального файла.

### DOC-008 — Паспорт: архитектура и функции
Статус: обязательное. Источник: «Требования к паспорту проекта — Страница 1; Страница 2».

Требование: указать версию и способ развертывания Kubernetes, Gateway API, автоматизацию, Fluentd/Filebeat, способ развертывания Prometheus, тестовую ОС и простую архитектурную схему. Для обязательных пунктов и реализованных улучшений указать реализацию, обоснование и проверку.

Проверка: сверить паспорт с репозиторием и проверками. Доказательство: страницы паспорта и ссылки на реализацию.

### DOC-009 — Паспорт: ревью и развитие
Статус: обязательное. Источник: «Требования к паспорту проекта — Страница 3».

Требование: кратко описать сильную техническую сторону, самое сложное решение с альтернативами и основаниями выбора, а также предложения дальнейшего развития и условия их реализации; для каждого пункта — не более трёх предложений.

Проверка: проверить наличие разделов и объём текста. Доказательство: соответствующая страница паспорта.

### DOC-010 — Проверяемость заявлений паспорта
Статус: обязательное. Источник: «Требования к паспорту проекта — Важно».

Требование: все заявленные работающие возможности подтверждаются содержимым репозитория и воспроизводятся экспертами; паспорт не заменяет репозиторий.

Проверка: сопоставить каждое заявление паспорта с файлом и проверкой. Доказательство: ссылки и результаты.
