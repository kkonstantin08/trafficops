## Pod delete scope

**Known least-privilege limitation:** delete pods в namespace trafficops возвращает **YES**, и actual Role не содержит resourceNames для pods. Это permission на любой pod данного namespace, включая controller/не-demo pods; тест не выполнял реальный delete. В kube-system delete pods — NO.

Kubernetes RBAC не задаёт label selector restriction для этого delete grant. Ограничения имён и wildcard semantics описаны в [официальной RBAC документации Kubernetes](https://kubernetes.io/docs/reference/access-authn-authz/rbac/). Actual controller application logic отдельно делает GET pods с labelSelector app.kubernetes.io/name=demo, выбирает первый Running demo pod и DELETE по имени (controller/clients.py: demo_pods/restart_one_pod). Этот фильтр **не является Kubernetes authorization boundary**: effective RBAC capability шире application intent. Заявление про выбор pod основано на чтении exact revision code; destructive path в этом этапе не выполнялся.

Это не скрывается и не считается автоматическим FAIL по условиям этапа: grant соответствует текущему manifest; RBAC и код не исправлялись.
