# Проверка панели и исправление отображения метрик

1 октября 2026, Europe/Moscow. Источник — скриншоты пользователя из продолжающейся проверки VM; агент к VM не подключался.

[Скриншот восстановления pod](vm-pod-recovery-2026-10-01.png) показывает `succeeded · результат записан в журнал`. Просмотренный контроллер выдаёт успех после исчезновения удалённого pod, появления replacement Ready и HTTP probe через Gateway. На том же скриншоте раздел диагностики `available`, собранные access-логи v1/v2 и HTTP 200 для `/demo`.

Второй скриншот подтверждает завершённую серию 10 запросов/с на 30 секунд: отправлено 300, ошибок 0. При этом график скрыт из-за `Prometheus series is non-finite for latency_p95`. Третий показывает активный canary, незаполненное окно и отказ повторного старта `an active release already exists`; это не доказательство ошибки canary.

В `controller/clients.py` общий metrics response раньше становился unavailable из-за NaN любого ряда. [Prometheus описывает NaN для histogram_quantile без наблюдений](https://prometheus.io/docs/prometheus/2.55/querying/functions/). Исправление исключает только неопределённые NaN-ряды latency_p95; пустой p95 допустим, UI показывает «Неизвестно». Остальные доступные ряды сохраняются. Infinity, некорректные обязательные метрики и несвежие timestamps по-прежнему дают unavailable. Canary использует отдельный строгий canary_snapshot и не изменён.

Целевой тест сначала падал; после изменения проверены отсутствие p95, смесь NaN v2 с известным p95 v1 и отказ при NaN memory. Повторная визуальная проверка метрик после deploy остаётся открытой. OPT-005 остаётся частично до негативной проверки Origin/CSRF в VM; восстановление pod подтверждено скриншотом. OPT-003 остаётся частично до проверки исправления в VM.

Полный локальный unittest на macOS: 34 теста за 8.085 секунды, OK. `git diff --check` — exit 0. Эти проверки не заменяют визуальную проверку исправления в VM.
