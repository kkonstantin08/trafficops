`make bootstrap` вызывает sudo bootstrap; `make deploy` собирает образ, импортирует его в containerd `k8s.io`, применяет ресурсы и **в конце сам запускает verify**. Отдельный `make verify` повторяет проверку. Demo/controller используют `imagePullPolicy: Never`, поэтому импорт локального образа — часть обязательного пути. Повторный deploy сохраняет веса существующего demo HTTPRoute, переключатель ошибок и credentials. Хранилище одноузловое; capacity local PV не является дисковой квотой.

## Baseline conclusion

На `8a4ae602fa809f462b11653f3479c02be9d95c5b` существует публичная реализация всей обязательной технической связки и успешный CI. Пользовательское evidence подтверждает работу Gateway → приложение, Prometheus, Fluentd, повторный deploy и release/rollback сценарий на заявленной Ubuntu 24.04 ARM64; часть UI/recovery подтверждена скриншотами. Это существенно больше, чем наличие YAML, но меньше, чем чистое воспроизведение текущей ревизии.

Решение пока нельзя объявить готовым к сдаче: не доказан clean bootstrap на Noble, AMD64 путь текущим кодом не поддержан, матрица/README/паспорт требуют сверки, финальный комплект отсутствует. Код, манифесты, deployment logic, controller и UI в рамках baseline не изменены.
