# Исправление bootstrap после kubeadm init

1 октября 2026, Europe/Moscow. Пользователь прислал вывод Ubuntu 22.04.5 ARM64 VM: kubeadm сообщил успешную инициализацию control plane, затем bootstrap остановился на `kubectl taint`: `unknown flag: --ignore-not-found`. Полная готовность кластера этим выводом не подтверждена. Join credentials из вывода не сохраняются в репозитории.

В `scripts/bootstrap.sh` удалён неподдерживаемый флаг. Перед снятием control-plane taint скрипт получает текущие ключи taints; при отсутствии нужного ключа снятие пропускается. Ошибки получения узла и снятия taint останавливают bootstrap. Существующий управляемый кластер продолжает использоваться без повторного kubeadm init.

Целевая локальная проверка на macOS: `python3 -m unittest discover -s tests -p 'test_bootstrap*.py'` — 4 теста, OK. Новый тест выполняет реальный shell-блок с подменённым kctl: проверены наличие taint, повторный запуск без него, ошибка чтения API и ошибка удаления. До изменения тест падал. `bash -n scripts/bootstrap.sh` и `git diff --check` — exit 0.

Связанные требования: DEP-004 (автоматизация) и DEP-005 (повторный запуск); фактический повторный bootstrap в VM и DEP-001 остаются открытыми до получения результатов. Проверка с подменённым kctl не является доказательством готовности Kubernetes.
